Blockpilot · step 1 of the build

Do people put the next block right next to the last one?

A 2019 paper measured this on 2,517 recorded Minecraft builds and published the answer. Your job is to compute the same numbers from the same files. If you match them, your code reads the data correctly.

01 · the point

Why this is the first thing you build

You have 2,517 folders on disk. Each one holds a list of every action a person took while building something in Minecraft, in the order they took it. Nobody documented the format. You worked most of it out by opening a file and reading it.

The risk now is that you think you understand it. A misread field doesn't crash anything. It quietly produces a model that trains, converges, and is wrong, and you find out three weeks later.

So before writing a model, you compute numbers that someone else already published. Match them, and your reader is correct. Miss them, and you learn exactly which assumption was wrong, today.

The word for this

Reproducing a published statistic to test your own pipeline is a sanity check against ground truth. It costs an afternoon and removes an entire category of silent failure.

02 · coordinates

Where a block lives

Minecraft is a grid of cubes. Every block sits at a whole-number position written as three values:

(x, y, z) ← x and z run flat along the ground, y is height

Two details that matter:

  • y is up. In most 3D graphics work z is up. Here it isn't. Getting this backwards silently turns every building on its side.
  • Numbers can be negative. These are world coordinates, not offsets from a corner. A real row from your data reads [-9, 72, 5].

03 · distance

Two ways to measure how far apart two blocks are

The claim you're testing is "the next block goes right next to the last one." To test it you need to turn "next to" into a number. There are two reasonable ways, and they disagree.

Way one: straight-line distance

The distance you'd measure with a ruler. Also called Euclidean distance.

d = √( dx² + dy² + dz² )

Way two: step distance

How many single moves it takes to walk from one cube to the other, where a move goes through one face of a cube. Add up the three gaps and don't square anything. Also called Manhattan distance, or L1, because it's how far you walk on a street grid.

d = |dx| + |dy| + |dz| | | means "throw away the minus sign"

A worked example, using real rows from your data

block A = (-9, 72, 4) block B = (-9, 73, 2) dx = -9 − -9 = 0 → |0| = 0 dy = 72 − 73 = -1 → |-1| = 1 dz = 4 − 2 = 2 → |2| = 2 L1 distance = 0 + 1 + 2 = 3 three steps apart Euclidean = √(0+1+4) ≈ 2.24 a number with no obvious meaning here

Why the paper uses L1

Because on a grid of cubes, L1 = 1 means the two blocks touch face to face. There are exactly six such positions: one up, one down, and four sideways. That's precisely the situation you care about, and L1 is the only measure that isolates it.

Straight-line distance blurs it. A block placed diagonally across an edge is 1.41 away, and across a corner 1.73. Those are all "about 1," so "distance 1" stops meaning anything specific.

Sanity check on the diagonals

Under L1, an edge diagonal is 2 (one sideways step, one up) and a corner diagonal is 3. Nothing is 1 except the six face neighbours. That crispness is the whole reason to use it.

04 · the third measure

A third measure shows up later, and it is not the same shape

The 2019 model doesn't guess anywhere in the world. It only guesses inside a small box around your last block: 7 wide, 7 tall, 7 deep, which is 343 possible spots.

That box is defined by a different distance: take the biggest of the three gaps and ignore the other two. It's called L∞, and "the box" is every cell where L∞ is 3 or less.

L∞ = the largest of ( |dx| , |dy| , |dz| )

So the paper reports its histogram in L1 but sizes its model in L∞. Two measures, two shapes. Play with the grid below until the difference is obvious, because conflating them is a real bug waiting to happen.

← x → horizontal   ·   ↑ z ↓ vertical   ·   orange cell = your last block

The trap

"Within 5 steps" and "inside the 7³ box" are not the same set of cells, and neither one contains the other. Switch between the last two modes at y = 0 and watch the corners turn off while the far edges stay on.

05 · the hard part

What "consecutive" means, which nobody wrote down

To measure the distance between one block and "the previous block," you need to know which block counts as previous. That sounds obvious. It isn't, because the recording contains two kinds of action.

Every line in the file looks like this:

[tick, player, [x,y,z], [block_id, meta], "P" or "B"] P = placed a block B = broke a block

People don't only build. They clear the ground, cut a window into a finished wall, and change their minds. In the house you opened there were 939 placements and 530 breaks. Over a third of the actions destroy something.

So "the previous block" has at least three defensible meanings. Here is a real 8-action stretch from your data, measured three ways.

Definition A — every action counts

Take the file line by line. The previous action is whatever came before, place or break.

Definition B — placements only

Skip every break. The previous block is the last block actually placed.

Definition C — placements that survived

For each position, keep only the last thing that happened there. If a block was placed and later broken, it was never part of the finished build, so drop it.

Same eight rows, three different answers. Notice what Definition A produces that the others don't: a distance of 0, because a block was placed and then broken at the identical spot. A zero would pollute your histogram with a "distance" that isn't a move at all.

06 · cleaning

The paper cleans the data first, and every step pushes the number up

The paper states that all of its statistics come from cleaned data, and lists three cleaning steps. Understanding why each one exists tells you which direction it moves your answer.

StepWhy it existsEffect on locality
Keep only the last action at each positionPeople place, break, and replace the same spot. Only the final state is part of the build.↑ raises
Drop caves and underground sheltersThose builds are mostly breaking into a hillside. The few placements are scattered and unrepresentative.↑ raises
Keep only the largest connected structurePeople drop stray blocks far from the build. Each stray adds one enormous jump.↑ raises

This gives you a prediction to test. If your uncleaned number comes out below 67.9%, that's expected, and the gap tells you how much of the published figure is cleaning rather than human behaviour. If your uncleaned number comes out above it, something is wrong with your code, because cleaning can only push it higher.

Why that matters

You now have a result you can interpret either way. That's what a good check looks like: it can't come back "inconclusive."

07 · method

Don't pick a definition. Let the published number pick it.

You can't ask the authors which definition they used, and their code doesn't spell it out. So don't guess and hope.

Compute the statistic under all three definitions and see which one lands on 67.9%. The published number becomes a test you run against your own choices.

08 · build it

What the script has to do

  1. Walk every folder under data/houses/ and load its placed.json.
  2. For each of the three definitions, build the list of positions in order.
  3. For each neighbouring pair in that list, compute the L1 distance.
  4. Report what fraction of pairs are exactly 1, and what fraction are 5 or less.

Roughly 1.5 million placements total. Plain Python and the json module handle it in seconds. You need no PyTorch and no NumPy for this.

Five things that will bite you

  • Never pair across two buildsReset at every house. The distance between the last block of one build and the first block of the next is meaningless and will drag your average toward nonsense.
  • A build with n placements gives n−1 pairsThe first block has nothing before it. Your denominator is the number of pairs, not the number of blocks.
  • Normalise block ids with & 0xFFThe file stores ids as signed bytes, so id 191 appears as −65. You don't need ids for the distance figure, but you do for the block-type figures, and getting it wrong splits one material into two.
  • Block id 0 means airCheck whether any P action places air. Verify it rather than assuming it.
  • 2,517 folders have placed.json, but 2,537 have a schematicThe counts disagree. Decide what makes a build usable and state it, or your totals won't reproduce anyone's.
Before you write code

Write decision 002 first: how do you define a step, and how will you settle it? The answer is "empirically, against the published 67.9%" — which is itself a choice worth recording.
